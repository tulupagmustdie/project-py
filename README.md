# File Organizer

Консольная программа для анализа файлов в папке: просмотр метаданных,
классификация по расширениям, предварительный план сортировки и статистика.
По подтверждённому плану программа перемещает файлы в подпапки категорий.

Требуется Python 3.11 или новее. Дополнительные зависимости не нужны.

## Запуск

Из папки `file_organizer`:

```sh
python3 main.py
```

При запуске можно прочитать предыдущий отчёт, ответив `д`.
Он выводится как JSON и не загружается в текущую сессию сканирования.

```text
1. Сканировать папку
2. Показать классификацию файлов
3. Показать статистику
4. Разложить файлы по папкам
5. Выйти
```

Выберите `1` и введите путь, например `~/Downloads` или `test_files`.
Путь с пробелами вводится без кавычек. Относительные пути отсчитываются
от текущей рабочей папки. Пункты `2` и `3` используют результаты последнего
успешного сканирования в памяти. Для обновления списка файлов выберите `1` снова.

Пример предварительного плана:

```text
lecture.pdf -> Документы/
photo.JPG -> Изображения/
unknown.xyz -> Прочее/
```

При просмотре классификации папки категорий не создаются. Статистика включает количество и общий размер
файлов, количество и размер каждой категории и её долю в числе файлов.
Проценты на экране округляются до одного знака, поэтому их сумма иногда
может немного отличаться от 100%.

## Правила классификации

Правила находятся в `config.json` рядом с `main.py`. Каждой категории
соответствует список расширений:

```json
{
  "Документы": [".pdf", ".txt"],
  "Изображения": [".jpg", ".png"],
  "Прочее": []
}
```

Это сокращённый пример. В комплекте также есть категории таблиц,
презентаций, видео, аудио, архивов, установщиков и кода.

Чтобы добавить формат, внесите расширение в список нужной категории
и сохраните файл в UTF-8. Следующий выбор пункта `1`, `2`, `3` или `4` перечитает
конфигурацию. Регистр не важен; недостающая начальная точка добавляется.
Повторы в одной категории убираются, а одинаковое расширение в разных
категориях считается ошибкой. Названия категорий должны быть уникальными
ключами JSON; используйте непустые строки.

При отсутствии файла, повреждённом JSON или некорректной структуре правил
действие отменяется. Предыдущий отчёт сохраняется; резервные правила
не подставляются.

## Сканирование и ограничения

- Обрабатываются только файлы непосредственно в выбранной папке.
- Скрытые файлы, вложенные папки и символические ссылки пропускаются.
- Для `report.final.pdf` берётся `.pdf`, для `archive.tar.gz` — `.gz`.
- Неизвестные расширения и файлы без расширения относятся к «Прочее».
- Кириллица и пробелы в именах поддерживаются; файлы нулевого размера учитываются.
- Пустая папка даёт нулевые итоги без деления на ноль.
- Ошибка метаданных одного файла даёт предупреждение; остальные обрабатываются.
- Ошибка чтения всей папки отменяет действие и не перезаписывает отчёт.

Категория определяется только по расширению, содержимое файла не анализируется.
Список в памяти является снимком: внешние изменения файлов видны после нового
сканирования. Ошибочные файлы, пропущенные с предупреждением, в итоги не входят.

## Отчёты

После успешного сканирования или просмотра классификации/статистики отчёт сохраняется в `data/last_scan.json` относительно
папки программы. Он содержит путь и дату сканирования, дату классификации,
снимок правил, метаданные и категории файлов, общие итоги, статистику
по расширениям и категориям.

Новый JSON сначала записывается во временный файл рядом с отчётом, затем
заменяет предыдущий. При ошибке записи или замены предыдущий файл остаётся
на месте; результат текущего действия остаётся доступен в памяти.
Каталог хранения отчётов нельзя выбрать для сканирования, чтобы запись
отчёта не меняла содержимое сканируемой папки.

## Структура

- `main.py` — меню и последовательность действий.
- `scanner.py` — проверка пути и сбор метаданных.
- `classifier.py` — загрузка правил и классификация.
- `config.json` — категории и расширения.
- `report.py` — план сортировки, расчёты и вывод.
- `storage.py` — сохранение и чтение JSON.
- `sorter.py` — подготовка и выполнение перемещений.
- `tests/` — автоматические проверки.
- `data/` — локальные отчёты.
- `test_files/` — локальные примеры и временные файлы тестов.

Содержимое `data/` и `test_files/` исключено из Git, кроме `.gitkeep`.

## Проверка

Из папки `file_organizer`:

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты создают временные данные только внутри `test_files/` и удаляют их
после проверки. Проверяются классификация, конфигурация, статистика,
чтение отчётов, сохранность предыдущего отчёта при ошибках и работа меню
без лишнего сканирования. Ошибки доступа имитируются независимо от прав
текущего пользователя.

## Сортировка

После сканирования выберите пункт `4`. Программа перечитает правила и покажет
точные назначения, например `lecture.pdf -> Документы/lecture.pdf`.
Только точный ответ `да` запускает перемещение. Любой другой ответ отменяет
операцию. До подтверждения этот пункт не создаёт папки и не записывает отчёт.

Папка категории создаётся перед попыткой перемещения или используется уже
существующая. Конфликтующее имя никогда не перезаписывается: файл пропускается.
Чтобы решить конфликт, самостоятельно сравните файлы, при необходимости
измените имя одного из них и заново просканируйте папку.

Пропускаются исчезнувшие или изменившиеся после сканирования файлы, папки,
символические ссылки и скрытые файлы. Если имя категории небезопасно
(например, `../Документы`), план отклоняется. Файл или ссылка вместо папки
категории также не используется. Ошибки доступа выводятся отдельно, обработка
других файлов продолжается, когда это безопасно.

После попытки сортировки показываются числа перемещённых, пропущенных файлов
и ошибок. Текущий снимок сбрасывается: перед следующей сортировкой, просмотром
статистики или классификации нужно снова выбрать пункт `1`.
Существующий JSON остаётся снимком до сортировки, а не текущим состоянием папки.

### Способ перемещения и ограничения

Используется жёсткая ссылка (`os.link`) и удаление исходного имени (`unlink`)
после проверки. Целевое имя создаётся без перезаписи, даже если другой процесс
успел занять его непосредственно перед операцией. Данные остаются доступны
под новым именем. `shutil.move()` не используется, поскольку он может
перезаписывать назначение.

- Источник и назначение должны находиться на одной файловой системе,
  поддерживающей жёсткие ссылки. Иначе перемещение завершится ошибкой.
- Не меняйте одновременно исходные файлы и папки категорий другой программой:
  проверки не обеспечивают полной защиты от такой подмены между операциями.
- Изменения определяются по размеру, точным временам и идентификатору файла;
  содержимое не хешируется.
- Если создать новое имя удалось, а убрать исходное — нет, оба имени могут
  остаться. Это один файл: изменение содержимого через одно имя видно через другое.
- После ошибки может остаться пустая созданная папка категории.
- Автоматической отмены и журнала перемещений нет.

### Безопасная ручная проверка

Создайте отдельную папку внутри `test_files/` и положите туда копии нескольких
ненужных файлов. Запустите программу, просканируйте эту папку, проверьте план
пункта `4`, сначала откажитесь, затем повторите и подтвердите. После перемещения
просканируйте её снова. Не используйте важные оригиналы для первого знакомства.

Автоматические тесты дополнительно проверяют отказ, существующее назначение,
его появление непосредственно перед перемещением, ошибки доступа, изменённые
источники и обновление состояния после повторного сканирования.
